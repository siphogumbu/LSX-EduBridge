Architecture

Offline-first by design

01 • Client layer

  • Android app optimised for low-spec devices
  • On-device adaptive diagnostic engine
  • Local SQLite content and progress store

02 • Sync layer

  • Background delta sync over Wi-Fi
  • USSD/SMS summary fallback concept
  • Conflict resolution after offline periods

03 • Backend & content

  • Cloud API and analytics database
  • Curriculum-tagged content repository
  • Teacher/school web dashboard

Design principle

Every core learning function works with zero connectivity. The network is used to synchronise, never to gate access.

TRL 3 → TRL 4–5 roadmap

Current: simulated adaptive engine, offline storage/sync proof, early usability walkthroughs.
Next: classroom pilot, wider low-cost device testing, curriculum alignment with subject specialists.
